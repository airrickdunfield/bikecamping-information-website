# Bikecamping Website

## Overview
This is a new project that is a companion project to my bikecamping (bicycle) map that I've made to show off locations in BC. That project is a web app, where this project serves more as a informational site.  It will contain a Home page, an About Page, Gear Page with the following sub pages: Bikes, Bags, Tents and a Community groups page. The content for those pages will begin as dummy content which I will write later. This project serves as a starting point for a new bike camper

## Target User
This website has two important users. I am the first user who is a developer with minimal coding experience who is building this project with the help of AI, please make sure to talk to me in a way I can understand as you work. The other is people who are curious about bike camping, but haven't gotten started yet. When reviewing my writing, make sure it isn't filled with jargon and is easy read

## Tech Stack
React.js is the website type I'd like to use. Eventually I would like to use WORDPRESS to manage the data, but for now it's just react. React and Vite are approved for the initial project setup. When creating or changing the React/Vite setup, always include a `vite.config.js` file with `@vitejs/plugin-react` so React JSX works correctly in development and production builds. Put React app source files in `src/`, with `src/main.jsx` as the browser entry point.

Keep build tools like Vite and React plugins in `devDependencies`. Add or maintain a `.gitignore` early so generated files like `node_modules/`, `dist/`, and `.DS_Store` are not tracked.

For an animation library, research the library that is most used with React.js and use it consistently across the project. Do not add extra libraries, including animation libraries, routing libraries, UI kits, or CSS frameworks, without checking with me first. If you are adding a library or revising over 500 lines of code, check in with me before you do that.

## Constraints
Always write code in a way that is human readable and includes comments. When taking direction, prioritize my general descriptions over my technical terms as I am not an experienced developer.

Before creating or changing more than 500 total lines, pause and check in with me. This includes new scaffold files, CSS, README changes, and config files.

## Working Style
Never store API keys directly in my files and store them safely instead. At the start of each project session, review the code base for common AI errors that might need to be fixed.

Some project commands may need approval because this environment uses a sandbox. `npm install` may need network permission, and `npm run dev` may need permission to start a local server. If a command hangs silently, stop and explain what happened before retrying.
